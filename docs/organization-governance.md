# Organization governance

`/organizations` is a separate organization workspace. It brings together only the project aggregates that a current project organizer and a current organization owner/coordinator explicitly approve. Organization membership never grants a project role, access to private claims or evidence images, pooled money, or authority to approve a payment.

## Entry and membership

An organization creator receives an original possession-based owner capability. Owners may share one-use owner, coordinator or auditor invitations through `/organizations/join`. Names are self-declared; this does not verify a legal entity, person, email address or PayPal account. The inviting browser cannot accept its own invitation. No email is sent.

Creation, acceptance and restoration bind the original browser, command intent, membership and session. Private links carry their secret in a URL fragment and private request body. Fixed deadlines are capped by the original authorizing profile. A reload or saved-profile switch restores that same session and deadline. Expired or revoked credentials require an explicit clear action before another profile can be opened. An unused invitation also requires its original inviter's current owner authority. An accepted member remains independently governed; explicit invitation withdrawal ends that accepted member and their original session. The last current owner cannot be removed or demoted.

Organization cookies and the saved organization library are separate from project cookies. A current organization role, membership version and session are checked again after locks and before returning private results. A project role switch invalidates only the project side of a dual-authority request. Owner-only rosters and policy drafts are absent for auditors.

## Project disclosure and reusable policies

A link review pins both actual current profiles, the original project package/plan/source basis, the chosen aggregate sections and a deadline no later than either original profile. Either authority can withdraw disclosure. Role changes, revocation, expiry or a changed authorizer version suspend it. Re-review creates a new immutable consent revision; old consent records remain.

Reusable package libraries, funding rules and evidence rules have editable drafts and immutable published versions. Adoption requires the separately held current project organizer, an active disclosure, a current published policy, exact target-package mappings and a reviewed project basis. The project receives its own copied rule and immutable source lineage. Retiring a reusable version or ending aggregate disclosure cannot silently rewrite that project rule. A current project organizer may review an independent replacement or deliberately deactivate prospective enforcement while retaining all prior history.

Package libraries and evidence rules materialize an editable target plan. Required review items and prerequisites must survive real plan review and publication; a materialized draft alone is not current compliance. Canonical package changes are an additional explicit choice requiring target-specific reviewed quotes. They are permitted only for untouched open packages without original promises, collections, claims, allocations, image associations or work-review history. Original package/project values and reviewed quotes remain in an immutable revision.

Funding rules guard new purpose terms, sponsor offers/acceptances, pledges, expense reviews and payable approvals. Actual consumer IDs and content hashes are bound to the copied rule. A payment review also pins an explicit empty rule set, so adding a rule before approval requires a new review. Existing accepted promises, original donor choices and approved payment requests retain their original contracts; later rules cannot redirect or replace them. Evidence source provenance and image-sharing restrictions are checked in the real image and physical-review constructors. None of these decisions invokes a provider or model by itself.

## Aggregate portfolios

The portfolio reads approved sections at one coherent database cutoff. It separates planned budgets, original gross/credited receipts, current purpose positions, unpaid promises, reviewed expenses, original delivered/returned principal, current paid principal, unresolved reservations and known fees. Unknown/conflicting fees remain unknown. Currency and Sample/Sandbox provenance groups stay separate. Coverage denominators include only the relevant explicitly disclosed projects.

A saved edition is immutable and bound to its original organization member, role and membership version. Its current permission checks use a private dependency record; private actor, receipt, document and provider identifiers never appear in the organization projection. Later ordinary activity makes an edition historical without rewriting its figures. Revoked disclosure, expired original authority, withdrawn counted sources or ended counted reviewer authority withhold the old report, print and CSV content. A changed filter cannot relabel an unchanged saved edition.

The CSV includes the same complete scoped edition, original cutoff/hash/filters, per-section coverage, currency/provenance groups and per-project lineage. Spreadsheet formula prefixes are escaped. The print view uses the same audience and edition, with A4/Letter layouts and current permission gates. A portfolio is aggregate oversight, not a consolidated bank balance, payment approval or proof that physical work occurred.

## Storage and qualification

Schema 21 adds twenty organization/governance table families and their immutable/versioned/scope guards. No old financial row, identity, original session or deadline requires conversion. Existing installations require a reviewed additive schema20-to21 migration before deploying code that requires schema21; the initializer is for a new development database.

Controlled tests use disposable schemas and explicitly synthetic actors. They cover independent acceptance, concurrent inviter changes, last-owner protection, same-intent recovery, actual policy consumers, canonical empty-package restrictions, project-only replacement, aggregate disclosure boundaries and source withdrawal. A separate payment-constructor control uses unusable fixture configuration and blocked external networking; it makes no provider request. Browser, hosted release, independent human review and physical-work evidence remain separate qualification gates.
