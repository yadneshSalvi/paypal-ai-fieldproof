# Public recognition, by independent choice

Recognition is a live, permission-checked wall beside an existing public Proof Page. It is not part of an immutable Proof Page or Board edition. It adds no payment, provider, identity-verification, email or physical-work claim. Default is private. The ordinary profile's private display name is never read by this unit or used to fill the empty public-label field.

An independently entered donor (including sponsor-as-donor) or volunteer types up to40 plain-text characters, selects the exact current public page and acknowledges visibility and self-declared provenance. A current read-only preview shows that exact label/destination; a separate confirmation saves a new immutable consent version. An organizer cannot give consent, rename a participant, or undo suppression. Their view contains only currently public labels and opaque, scope-bound suppression handles, with an explicit privacy/moderation reason. A participant can independently withdraw an original listing even when its public proof is unavailable. Private history remains, but withdrawn/suppressed/withheld responses contain no old label.

## Authority and persistence

The source adapter uses `readOrganizationProjectAuthority` to read the actual cookie-backed project session. It then requires an exact single-role membership (`[donor]` or `[volunteer]`) and a current independent entry. Broad Sample role-switcher profiles are ineligible. Existing supporter access and joined reviewer invitations qualify. Procurement23 is optional: both entry tables must be in the sole current schema, and the approved joined/version2/volunteer/membership1/original-matching-deadline projection must hold. No private identity or capability columns are read. Missing/partial families fail closed. The reviewer-entry family's original session may be longer than its invitation; recognition ends at the earlier original deadline.

Every accepted grant pins tenant, project, actor, role, mode, membership version, actual token hash, original session ID, original six-digit PostgreSQL expiry, independent-entry ID/deadline, public slug, current proof snapshot/hash and reviewed head key. The non-authorizing access digest is purpose-separated HMAC, including the credential, fixed expiry and entry. An instruction that never reached the server cannot adopt an altered same-token expiry or another token with the same deadline. Current role/membership/session/entry checks run again after locks, storage and serialization. The supported role-change/revocation paths advance membership versions; restoring earlier token/role/version fields through arbitrary out-of-band database edits is outside that authority contract. This unit does not invent a global role-generation field.

All four `fp_recognition_*` tables and their functions/indexes/triggers live in additive `RECOGNITION_SCHEMA`, reserved fragment24. It never installs a global marker, changes old tables or backfills people. Deferred composite foreign keys bind a head to its exact actor/project/role/slug consent and vice versa. Current-version guards prevent reusing an old consent as a new decision. Consent/session/project/membership/proof lineage is checked on insert. Consent versions, commands and audit are immutable; each trigger installs independently and the read/write boundary refuses an incomplete guard set. Names and original command/provenance inputs are encrypted with purpose-specific authenticated contexts. Application eligibility is checked before decryption/disclosure.

One local transaction commits the effect and minimal immutable receipt. There is no external dispatch or orphaned pending reservation. A repeated exact intent returns that same receipt; changed body/scope/version conflicts. Receipts contain no label or historic visibility claim. Current visibility is a separate current read, so replaying an old accepted consent cannot republish a withdrawn name. Recovery is exact-session GET-first, including after remount/restart. An exact404 permits an explicit unchanged retry only after another current preview. Pending requests block another mutation. A checked404 plus an obsolete-version/source refusal can be explicitly closed after a final status check; nothing is replayed automatically. The browser persists the original request before dispatch and refuses to send if that storage fails. Journals are private to the original non-authorizing access digest and never contain credentials.

## Public permission and freshness

`readCurrentPublicProofWithin(slug,tx)` is the integration-owned read-only seam. It checks the same current head, reviewer, reviewed derivative, source permission, plan and sign-off rules used by the public Proof Page. Recognition first takes a SHARE table lock on `fp_plan_source_controls` before any snapshot read, protecting the first-control-insertion boundary as well as existing rows. NOWAIT bounds that first lock; subsequent locks/statements have bounded timeouts. Contention refuses a disclosure rather than returning an older cached label. No GET creates a source control, consent, audit or session row.

Names require the exact reviewed current proof head/edition, original participant authority and consent head. A public withdrawal, source invalidation, new proof head/edition, session/entry expiry, membership/role change, personal withdrawal or organizer suppression withholds old labels. A republished edition requires a separate explicit participant decision. Public access is by its existing opaque proof slug, never by a private project ID.

Public DTOs contain only deliberately approved labels, Sample/self-declared provenance, current availability, the public proof URL, opaque page continuation and bounded freshness metadata. They exclude actor/member/session IDs, private source bindings, payment amounts/receipt presence, emails, capabilities, command inputs, private name history and hidden-name counts. Cross-field schemas and rendering guards reject contradictory withdrawn/unavailable responses carrying labels. All API responses set no-store/no-referrer/nosniff; HTML has no-referrer metadata. The integration owner must add the three recognition namespaces to the shared HTTP privacy-header map.

The public wall and private current-label view check at four-second intervals while visible and clear names at the earlier five-second freshness deadline or original access deadline, even if the next read hangs. Visibility/page lifecycle and actual cross-tab workspace changes clear content; obsolete responses are fenced by request generation and page/scope. Failed checks never redisplay prior names. Refresh reads and pending mutations are single-flight. Public copies already made by a visitor are not recalled by withdrawal; the guarantee concerns current Fieldproof reads and bounded open-view checks.

Pages show at most24 labels and inspect at most512 candidates. Continuations are encrypted, purpose-bound to the exact slug/current proof key and original cutoff. Both SQL keyset predicate and order use `date_trunc('milliseconds',consented_at AT TIME ZONE 'UTC')` plus the same unique consent ID. An empty continuation can occur; no hidden participant count is returned.

- `POST /api/recognition/review`: exact same strict command body, current preview only, no rows created.
