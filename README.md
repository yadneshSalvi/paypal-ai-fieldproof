# Fieldproof

**Every community dollar, linked to proof.**

Fieldproof connects a community project plan to conditional commitments, confirmed payments, reviewed expenses, and source evidence. Its visual language is a warm civic blueprint: a room gradually becoming something people can use.

The Eastside makerspace is a fictional sample project. Its Electronics Benches package has an exact $960 target and eight sample obligations. The walkthrough illustrates seven capture receipts totalling $925 and one $35 invoice-payment receipt. Sample records are never presented as real PayPal payments or physical work.

## Run locally

Use Node **22.22.3 or later** and npm. Provide a dedicated PostgreSQL database that this app may create tables in. No in-memory persistence fallback is used.

```sh
npm ci
cp .env.example .env
# Fill server environment values for your isolated sandbox app and database.
npm run db:seed
npm run dev
```

Open [localhost:4102](http://localhost:4102). The public sample can be explored without a login. “See it in 60 seconds” creates a separate persisted sample workspace. “Try the sandbox” opens a separate empty live sandbox workspace. A fresh workspace never erases PayPal history.

Those commands are for a new development database. In a checkout whose original workspace has been transferred and held, do **not** restart its retired writer. `npm run studio:qa -- --prepare` creates a distinctly named local review database, and `npm run studio:qa -- --resume` starts only port **4202** against it. If the configured app role lacks database-creation privileges, `--prepare --local-admin` uses an existing OS-authorized PostgreSQL administrator on `127.0.0.1:5432` to create a separate database and unprivileged QA role. It changes no existing database or role. Its private runtime is stored under ignored `.local/studio-qa/`; never copy or print it. PayPal and Blob credentials are disabled in the child process; server-side model configuration remains available. A separate QA cookie preserves the original localhost session. See [the Studio review procedure](docs/studio-review.md).

The Planning review uses a further isolated database, private local image storage and port **4502**. Use `npm run planning:qa -- --prepare --local-admin` once, then `npm run planning:qa -- --resume`. Its runtime secrets are under ignored `.local/planning-qa/`; the distinct cookie preserves both previous workspaces. `npm run planning:qa -- --test` runs disposable-schema tests with synthetic provider credentials, and `npm run planning:qa -- --build` builds into a separate output directory. Never use either review launcher to alter the original database. See the [Planning review procedure](docs/planning-review.md).

The checkout requires an actual PayPal sandbox buyer. Card details and buyer passwords stay with PayPal. The app never switches to PayPal's real-money host. Do not put server keys in `NEXT_PUBLIC_*` variables. The browser receives only the public client ID needed by PayPal's official JS SDK.

The exact intended identity callbacks are:

- Local: `http://localhost:4102/api/auth/paypal/callback`
- Hosted: `https://paypal-ai-fieldproof.vercel.app/api/auth/paypal/callback`

The hosted callback is registered and separately qualified. PayPal refused the local callback settings save; the local preview therefore blocks account connection until `PAYPAL_LOCAL_IDENTITY_CALLBACK_VERIFIED=true` is justified by actual registration. Set `APP_URL` to the matching origin, or use the validated local/Vercel fallback. `/privacy` and `/terms` describe this sandbox demonstration. Production hosting still uses PayPal sandbox.

## Boundaries and integrations

The generated `paypal` SDK is pinned to version 2.29.0 at Git commit `5d0df8a8817e5fdf2e2cd48e68f790ea4730aab2`. Workspace-local APIMatic TypeScript integration, authentication, model, endpoint, resilience, error and testing guidance informed the implementation. The [SDK integration record](docs/apimatic/typescript-integration.md) and [paypal-plan.md](paypal-plan.md) document the actual boundaries and failure handling.

`@fracture/paypal-core` is an independently installed immutable archive in `vendor/`, with provenance. Version **0.2.7** supplies SDK transport, encrypted operation documents, durable claims, current-authority gates, typed Invoicing/Payout endpoint boundaries, canonical event intake and exact-operation outcome reconciliation. Fieldproof owns its domain approval, session, obligation, recipient and canonical receipt authority. There are no sibling runtime imports.

An uncertain financial write remains unknown until reconciled. It is never treated as a decline or permission to open another collection channel. Authenticated `/api/cron/reconcile`, `/api/cron/webhooks`, `/api/cron/collection`, `/api/cron/compensation`, `/api/cron/invoices`, `/api/cron/refunds`, `/api/cron/evidence`, `/api/cron/planning`, `/api/cron/community` and `/api/cron/payouts` persist and reconcile their work. Payment recovery selects bounded original commands; Payout reconciliation only reads known provider resources. Planning continuations only poll saved model response identities; another inference requires explicit consent. Schedules are declared in `vercel.json`; newly added hosted jobs require deployment and provider registration qualification. In review-each collection mode, a background worker cannot initiate an untouched slot.

For the controlled collection qualification, keep the existing participant workspace, choose Organizer, open `/collection`, review the complete eight-slot set and explicitly start the round. Use each slot's Collect action. A failed request remains attached to its original record; use its check or recovery action instead of starting another workspace. The first conditional-collection allowance is exactly $960 across original collection commands and is separate from the $1 checkout ceiling. Cancelling a reviewed unspent round stops new collection and begins compensation; it never silently deletes provider history.

PayPal Invoice status and bookkeeping refund endpoints do not prove money movement. Payout submission does not prove successful repayment. A saved wallet is not reserved funds. AI proposals have no financial authority. The Auditor cannot dispatch financial commands.

Direct OpenAI and Gemini calls and private Vercel Blob storage are qualified for the receipt workflow, with run versions, source/output hashes and measured latency recorded. AG Studio 3.1.0 is integrated with native custom widgets, live data, full history and the retained composition harness. Its actual Sample browser/model journey is recorded separately from the official `@paypal/agent-toolkit@1.11.0` owned-resource provider gate. The Toolkit graph currently has 12 inherited npm advisories (11 high, one moderate); its closed read boundary does not make that audit clean. Dependency hardening and requalification remain required before release. Real physical evidence and real user research require authorized sources and participants. Clearly disclosed Sample alternatives are used where those do not exist.

The receipt pipeline validates files before model use, retains private originals and immutable model output, checks currency/arithmetic/source regions, and requires an organizer decision for every line. Payouts can use only reviewed, currently funded package allocations; a balance read is bounded to a 60-second fetch age and a disclosed three-hour provider reporting age. Batch acceptance is not item success. Unknown creation retains its reservations and exact original request identity. These gates have local fixture coverage; the separately observed original $66 sandbox reimbursement does not qualify every failure, refund or cancellation path.
